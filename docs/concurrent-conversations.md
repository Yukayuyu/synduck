# 同时进行多段对话（0.5.4）

在对话 A 输入问题并点「傳送」，接着打开对话 B，输入另一问题并传送。两段回答会同时进行；你可以继续创建对话、阅读、整理其他卡片，或从已保存文字摘录、延伸分支。无需额外开关。

每张卡片单独显示生成内容和「停止」按钮。桌面顶部显示生成中的对话数量，对话列表也有状态标记。停止 A 不会停止 B；A 的问题、原始上下文和停止记录会保留，点「使用原上下文重试」沿用同一输入。只有通过完整格式与来源检查的输出才会保存为可摘录的文字。

同一段对话一次生成一条回答，以保持问答顺序。在任何回答进行时，其他对话可以操作，但模型／账号切换、项目整体恢复和版本安装需等全部结束。各对话共享当前选定的模型、思考深度及账号额度；并行消耗同一个账号的额度，仍受模型服务的速率限制，停止前已消耗的 token 无法撤回。

每轮仍独立整理和封存上下文，预算不会因为并行而加大，也不会自动包含其他对话的临时生成文字。想带入其他对话的证据，请选择、固定卡片，或建立摘录分支。生成途中调整上下文选择只影响后续发送，已封存输入不会被改写。显式预览后如果画布发生变化，仍需重新预览；「傳送」会在开始回答时一次完成上下文整理和保存，避免不同对话之间的版本竞争。

## 安装更新

- **Windows 管理式安装**：在「版本與更新」匯入完整 `ContextCanvas-Windows-0.5.4.zip`，安装后重启整个启动器，再刷新页面。保留原安装的 `.env` 和 `data/`。如果仍使用 0.5.3，刷新网页不能更新正在运行的后端。
- **源码安装**：拉取 main，运行 `pnpm install --frozen-lockfile`、`pnpm build`，重启 `pnpm start:local`。
- **iPhone／iPad**：先更新提供服务的电脑，再重新打开 Safari 页面；它们使用相同后端的并行能力。

此改动不需要数据库 migration，不改变备份格式。更新包的构建与 GitHub Release 发布是分开的；线上能否发现新版，以 Releases 实际发布的版本为准。

## 实现与验证

客户端按 conversation ID 管理请求、生成文字及错误，停止操作指向具体 assistant turn。`POST /api/send` 原子执行上下文编译和开始回答，使用 UUID 请求编号防止重复发送；旧的 `/api/compile` → `/api/answer` 仍保留预览版本校验。数据库保留同一对话只能有一条生成中回答的约束。

ChatGPT / Codex 每次回答各用一个隔离的临时 thread，并根据 thread ID 分流事件。停止、超时、工具拒绝和清理失败只清理当前 thread；真实共享进程或网络连接丢失时，连接上的请求仍可能一同失败。OpenAI API 和 Demo 也各自接收取消信号。关闭页面的请求会停止，已保存的回答与错误仍可追溯。

自动化使用受控模型和官方协议模拟测试交错事件、独立取消、失败清理、引用校验、原上下文重试及 HTTP 断线，并在浏览器检查第三张卡片的输入、焦点和预览不被完成／停止事件覆盖。真实账号可同时运行的数量和速度取决于服务端额度，尚未在此云端环境用用户账号实测。
