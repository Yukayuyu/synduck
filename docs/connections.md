# 连接账号与服务

适用版本：0.13.0。连接入口在画布右上角的插头图标「连接账号与服务」。登录保存在运行 Synduck 的电脑上，同一安装中的所有画布与后续项目共用，不需要每个画布重新设置。

## GitHub：点按钮，在官方页面登录

1. 在普通画布输入「帮我连接 GitHub」，使用 ChatGPT / Codex 模型。AI 会在当前回答中显示「连接 GitHub」按钮。也可以直接打开顶部的连接入口，点 GitHub 的连接按钮。
2. 程序准备登录后，点「复制验证码并打开 GitHub」。在 GitHub 官方页面粘贴一次性验证码，完成本人登录并检查授权范围。授权页面显示官方登录工具 **GitHub CLI**，这是 Synduck 自动准备的官方组件。
3. 回到画布。显示账号后，原来的请求会继续；以后可以直接要求查看仓库、处理问题或访问已授权的私有项目。

不需要手动安装登录工具、创建 OAuth 应用、输入 GitHub token 或配置 MCP。首次连接需要网络，程序会下载固定版本的 GitHub 官方组件并校验文件；遇到暂时的下载问题会自动重试，并可切换到 GitHub 官方备用下载入口。ChatGPT 登录负责模型使用，GitHub 登录负责仓库权限，两者独立。

程序自动把这份 GitHub 登录交给本地任务中的 GitHub 操作，以及通过 HTTPS 访问 github.com 的 Git 命令；不会修改系统的全局 Git 设置。操作本地仓库仍需要电脑已安装 Git；SSH 使用已有的 SSH 授权。组织 SSO、管理员限制、仓库访问权限和服务额度以 GitHub 实际授权为准，登录不等于具有所有仓库的权限。

连接账号及调用已授权的服务不需要先选择本地项目。真正读写本机项目时，画布仍会提出目录授权；登录也不会替代每轮任务的操作许可。没有选择 ChatGPT / Codex 时，可以从顶部完成连接，但当前 API／演示模式不会因此获得本地工具。

## 其他服务

连接入口提供 Notion、Linear、Figma 和网页浏览。在线服务支持标准 MCP 网页授权时，会显示授权链接；打开服务方页面同意后自动继续。网页登录、凭据刷新和下次启动复用由程序处理。实际支持还取决于服务方是否开放自动应用登记、允许当前回调地址，以及账号方案／组织策略；预设不是对所有账号都可用的保证。

添加其他在线服务时，展开「添加其他服务」，填写名称与服务方提供的连接地址，再点「添加并连接」。地址需要 HTTPS；在同一台电脑测试可使用本机 HTTP 地址。只支持访问密钥的服务，可以展开卡片中的密钥入口，填写服务方签发的访问密钥；不要把密码或密钥发到对话里。不支持标准网页登录的服务不会凭空获得 OAuth 能力。

网页浏览使用后端电脑上已安装的 Chrome，首次会准备固定版本的浏览工具，需要网络。浏览器内各网站自己的登录仍由你完成。它不是 Windows／macOS 整个桌面的控制权限。

日常操作只需在画布说明需求。手动测试工具时，输入项显示为普通表单；操作确认显示自然语言说明和内容。原始记录放在折叠的追溯详情内。自定义本机程序仍可使用「高级连接设置」，启动选项按一行一项填写，不需要写 JSON 数组。

## 保存、断开与换设备

- GitHub 与在线服务凭据只保存在后端的数据目录 `data/local-runtime/connections/`，不放入回答、工具输出、普通连接状态或单张画布备份。现有高级服务设置仍兼容。
- 凭据是本机受限文件保存：在支持文件权限的系统上使用私有目录和仅拥有者可读写的文件；**并非加密保险箱**。完整安装／data 备份包含登录，须私下保存，勿上传仓库或分享给他人。
- 「仅从 Synduck 断开」删除此安装保存的相应连接。取消登录会让等待中的操作结束；不影响电脑上其他应用保存的登录，也不会撤销服务方账号页面的应用授权。需要彻底撤销时，在服务方的授权应用页面操作。
- 停止一次任务不会自动退出全局账号。服务登录与本轮任务权限分开管理；同一后端不是多人账号系统。
- 同一后端上的其他画布、浏览器或手机页面复用连接。另一份独立安装不会自动同步凭据。
- 在线服务授权绑定服务地址与后端回调地址。换端口、改公开访问地址或更换服务地址后，可能需要重新登录。远程访问需先设置可信 HTTPS 和工作区密码，见[跨设备指南](windows-ios.md)。

所有账号密码都在服务方页面输入。无需把密码、验证码或 token 发给 AI；一次性设备码只在当前连接卡片显示，不保存进操作追溯。
