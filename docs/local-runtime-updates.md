# 本地执行器、升级与恢复

适用版本：0.12.0。首次安装、模型接入和常用环境变量见[安装与配置指南](setup.md)。本页说明项目工具权限、数据保存位置，以及 Windows 管理式安装的升级与回退。

## 启用本地项目工具

1. 在「模型與登入」完成 ChatGPT 登录，选择可用的 Codex 模型与深度。
2. 在普通画布直接提供**后端电脑**上的项目目录及需求；目录尚未启用时，模型也有工具提出授权，不需要先手动配置。
3. 卡片显示待连接路径、后端系统和权限选项。「授權並繼續」保留写入／命令逐次确认；「授權並自動執行本次任務」允许本轮自动写入／执行命令。确认后验证目录，并在同一轮继续需求。只有明确请求创建时才可授权建立不存在的目录。
4. 项目设置会保存，任务自动执行权限只存在于当前运行中的任务，完成、停止、失败和重启都会收回。重启不重放。MCP 和桌面仍逐次确认。逐次批准的写入会显示原内容；确认期间被外部修改则原批准失效。
5. 所有参数、命令实时输出和授权关系保留在同一回答；顶部「本地任务」保留项目设置、整合与手动测试。`LOCAL_EXECUTOR_DISABLED=1` 显式禁用后端执行器时，不提供这些工具，需后端拥有者更改配置并重启。

项目工具支持列目录、读取 UTF-8 文本、提出写入和 shell 命令。项目目录是命令的工作目录，不是操作系统沙盒；操作以运行后端的 OS 用户权限执行。Windows 使用 PowerShell，其他主机使用 sh。任务子进程不继承模型密钥或 GitHub 发布凭证。

文件工具使用项目内的相对路径，不跟随符号链接，并拒绝 `.env` 等私密路径。命令默认 60 秒，最多 120 秒；任务最多 20 次操作、15 分钟，一次执行一个任务。取消会停止后续操作，但不会撤销已经完成的写入或外部副作用。

MCP、浏览器 MCP 和 Windows 目标窗口操作也可由普通画布对话自动调用，配置及证据回看见 [MCP 与桌面控制](mcp-desktop-traces.md)。普通对话仍使用已编译的画布输入包，工具证据额外受 100 KB 文本／8 张图片限制；工具记录不会自动修改画布、变成引用 source_id 或进入后续轮次的上下文。停止回答会撤销待确认的动作；有外部操作记录的失败回答需用新问题继续，不能直接重试重放。

## macOS 安裝包

Mac 0.12.0 起也使用管理式安裝、升級、備份與失敗回復。下載 `ContextCanvas-macOS-<版本>.zip`，啟動 `Start-Synduck.command`；首次啟動會準備原生 Node.js。Apple Silicon 與 Intel 共用一包。Mac 使用 `context-canvas-update-macos.json`，Windows 繼續使用 `context-canvas-update.json`，兩者不會互相安裝；完整說明見 [macOS 指南](macos.md)。

## 数据放在哪里

管理式安裝保持如下結構；Mac 根啟動檔是 `Start-Synduck.command`，Windows 是 `Start-ContextCanvas.cmd`：

```text
安装根目录/
  Start-ContextCanvas.cmd
  .env                   后端配置
  data/                  稳定的数据和登录目录
    context-canvas.sqlite
    model-settings.json
    codex/
    local-runtime/
  app/                   首次安装的应用
  versions/              后续安装的应用版本
  .runtime/              启动、暂存、更新与恢复记录
```

SQLite 的 WAL 等配套文件也属于数据。完整备份前停止后端，保留根目录 `.env` 和完整 `data/`。不要把登录、模型设置或数据移到 `versions/`，也不要删除 `.runtime/pending-install.json` 来绕过失败恢复。

「备份与恢复」导出的画布项目 JSON 保留文字、来源、分支和输入上下文；不包含 ChatGPT 登录、MCP 配置、本地任务或桌面图片。这些额外内容位于 `data/`，需要完整备份。

源码安装默认在仓库根目录保存同名数据。可配置其他路径；Windows 一键更新要求关键数据保留在稳定的安装根目录 `data/` 中。

## 检查与下载更新

打开「版本與更新」：

1. 选择只接收正式版，或接收测试版与正式版。
2. 选择是否自动下载新版。
3. 点「立即檢查更新」。有新版本时会显示提示并校验下载。
4. 需要系统提示时，在界面开启浏览器通知并允许浏览器权限。

后端运行期间每 15 分钟检查；自动下载不自动中断工作安装。后端关闭后不会继续检查，也不是离线 Web Push。通知与轮询不会要求页面重载。

0.5.3 起，客户端读取 `Yukayuyu/synduck` 的公开 Releases，与源码使用同一个仓库。用户不需要 `UPDATE_GITHUB_TOKEN`，程序也不读取它。公开仓库和正式 Release 附件是在线更新的前提，发布状态与规则见 [GitHub 发布配置](github-updates.md#当前状态)。

## 匯入 ZIP 并安装

可以下载公开 Release 的完整 ZIP，或使用维护者提供的可信新版本 ZIP：

1. 保存工作，结束 AI 和本地任务，并送出／清空未发送草稿。
2. 在「版本與更新」匯入 ZIP；包版本必须比当前版本高。
3. 等待校验和准备完成，点「安裝新版並重新啟動」。
4. 新版在独立 `versions/` 目录准备并安装依赖，旧后端在准备期间继续工作。
5. 切换前正常关闭旧后端，备份 `data/`，再启动新版本并核对健康检查和版本。
6. 新版启动成功后完成切换；失败时恢复上一版本及数据备份。

包格式、路径、大小、文件 SHA-256、数据 schema 与启动协议都会校验。线上下载还核对整个 ZIP 的 SHA-256，安装前再次校验暂存文件。SHA-256 用于完整性，不是独立的离线签名；请使用可信发布来源。

更新中启动器异常退出时，下次启动按 pending journal 恢复。旧版本、下载和备份暂不自动清理。未支持的数据 schema 迁移会被拒绝，不应绕过校验强行安装。

## 从更早的安装迁移

- 已有管理式更新界面：匯入完整的新版本 ZIP，安装后关闭整个启动器，再从原安装目录的 `Start-ContextCanvas.cmd` 启动。完整重启会载入新版启动器与更新来源。
- 旧包没有管理式更新：先停止旧程序，解压新包，运行**新包的** `Update-Existing.cmd`，选择旧安装根目录。工具保留旧 `app/.env`／`app/data/`，把副本迁移到稳定根目录后启动。

已存在 `.runtime/install.json` 的安装应使用界面匯入更新；旧安装转换工具会拒绝重复转换。不要为升级重新建立一个空工作区。

0.5.2 测试包读取先前的独立发布仓库，0.5.1 及更早版本读取最初的私有来源；这两类安装均需手动取得 0.5.3 或更新的 ZIP，匯入后完整重启一次，才能采用统一来源。以后改变发布仓库也需要安装包含新来源的版本；仅在 GitHub 改名或改公开状态不会改变本机程序。

## 源码更新与维护者打包

源码安装用 Git 更新：先停止后端，保留 `.env` 与 `data/`，再执行：

```sh
git switch main
git pull --ff-only origin main
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm build
pnpm start:local
```

拉取前先保存未提交修改。源码启动器可检查和暂存更新，但不会覆盖 Git checkout 一键切版。

维护者在已构建的 Git checkout 中运行 `pnpm package:windows`，输出位于 `release-output/`。打包从明确清单生成编译文件、前端、固定运行依赖清单、MIT 许可证和配置说明；没有真实 `.env`、数据或开发 `node_modules`。目标电脑首次启动时安装平台对应依赖。程序的 JavaScript 和桌面桥接仍可查看。

推送 `main` 运行 CI；对应提交通过后，推送匹配版本的 `canvas-v<版本>` 标签发布到更新频道，详见[发布配置](github-updates.md)。

## 验证范围

现有自动化覆盖项目读写、命令批准／拒绝／取消、重启记录、MCP fixture、模型动态工具协议、更新校验和真实安装／回退／中断恢复。Windows CI 覆盖原生桥接编译与窗口枚举，Linux CI 覆盖 Chromium 和 WebKit 手机布局。真实模型任务、实体 Windows 的截图／输入和实体 iOS 仍需实机确认。
